Start here

This workshop does two things: it generates publishable, fully-synthetic datasets from a vocabulary + AI, and it refines existing datasets for training. Pick the workflow that matches your situation — you normally move left to right through the tabs.

1 · Create a dataset with AI only (no own data)

Best for a fully synthetic, shareable set. Vocabularies (load the label list, e.g. Schulfächer) → Seeds (build a seed set, leave the reference empty = vocab-only; let the AI bootstrap examples) → Runs (dry-run for the cost, then start; add Context / guidance so it knows what the entries are about) → Review (approve / discard) → download CSV or push to api_v3.

2 · Blend your existing data into an AI set (hybrid)

Best when you have a curated CSV and want synthetic data in its style. References (upload the CSV — it is PII-scrubbed on import) → Seeds (pick that reference set; seeds are distilled from your rows) → Runs → Review → export. A leakage filter keeps near-copies of your data out of the result, so the output stays publishable.

3 · Clean up existing data

Best for tidying a dataset before training. Go to Refine: Analyze and Training preflight show what you have and the effective training set; then apply filters (dedupe, length, balance, mask PII, …) — each Apply writes a new dataset, so you can stack steps. Prepare for training makes an honest, text-disjoint holdout split.

Reminder: synthetic and enriched rows are for training only. Judge quality on a real, text-disjoint holdout — never on the synthetic rows themselves.

Generation runs

Generate synthetic samples from a seed set — vocab-only or hybrid, the seeds decide. Always dry-run first to see the cost estimate. Configured models: loading…

What does a run generate? (fields, label, length)

Each run produces catalog-style entries for every selected concept of the seed set's vocabulary. Per entry it writes three text fields — title, description, keywords — and one classification label: the concept itself, exported to the vocabulary's metadata field (e.g. properties.ccm:taxonid). These three fields are fixed because they map to the training columns of api_v3.

Example — school subjects: vocabulary Schulfächer (field taxonid), concept “Mathematik” → title “Bruchrechnung Klasse 6”, a 300–600-character description, keywords “Brüche, kürzen, Hauptnenner”. Length is set by the profile below.

Use Context / guidance below when the labels alone are not self-explanatory — it steers what the entries are about (e.g. “German school subjects, secondary level; realistic teaching materials”).

      Seeds

      A seed is a short example entry (title, description, keywords) that shows the AI the kind of material you want for one label. Per concept a handful of seeds steer the later generation so it stays on-topic and varied. You build a seed set here, review and edit it, then a Run generates the full dataset from it.

      Which mode should I use? (walk through the use cases)
      • Only AI + vocabulary (vocab-only): you have no own data, or want a fully synthetic, publishable dataset. Leave Reference set empty. The AI writes the seeds itself from each label and its place in the hierarchy. In the editor you can press Bootstrap to generate seeds for a concept.
      • Existing data + AI + vocabulary (hybrid): you have a curated CSV and want the synthetic data to match its style. First upload the CSV under References (it is PII-scrubbed on import), then pick it as the Reference set here. Seeds are distilled from your real examples; during the Run a leakage filter keeps near-copies of your data out of the output.
      • Mixed: subjects that have reference rows are seeded from them; subjects without any are bootstrapped by the AI — automatically, in one seed set.

                Prepare for training

                Stratified, text-disjoint holdout split (a holdout text never leaks into training) — honest evaluation. Uses the dataset and columns selected above.

                Label audit (second opinion)

                Ask a trained api_v3 model to review the labels. Rows where the model confidently disagrees with the gold label are listed for the editorial team — nothing is relabeled automatically.

                Enrich (additive, LLM)

                Fill gaps only — never overwrites existing content. Every change is recorded in an enriched_fields column.

                Minimum rows per label (LLM)

                Generates the rows each under-represented label is missing, from that label’s own examples. Preview first: it says how many rows and how many model calls that would be, without calling anything. Generated rows are marked and are kept out of the holdout when you split, so the evaluation stays honest.

                About nested JSON

                Nested objects become columns with dot paths, so properties.cclom:title is a plain column you can filter on. Lists of simple values are joined; a list of objects is kept as JSON text, because there is no sensible column for it. Whatever you import is stored as semicolon CSV, so every later step works the same way regardless of where the data came from.
