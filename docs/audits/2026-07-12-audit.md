## 1. Executive summary

data-prep is a **well-built, security-conscious, thoroughly-tested** application
whose fundamentals are strong: constant-time auth, a solid SSRF guard, no secret
leakage, PII scrubbing on publish paths, a separation guarantee pinned two
independent ways, and 219 fast deterministic tests covering error paths, not just
happy paths. The top three risks are all about **scale and process, not
correctness**: (1) two **O(N²) `np.vstack` semantic-dedupe loops** that will
thrash/appear-hung on the app's actual 30k-row target input; (2) the project is
**not under version control** (no history, rollback, or CI gate for the ruff/mypy/
pytest suite that already exists); (3) **heavy pandas/embedding work runs on the
single event loop**, so a big refine/import call freezes the whole process
including an in-flight generation run. The single most important action: **fix the
quadratic dedupe** (`filters.py` / `filtering.py`) — it directly breaks the
headline use case at realistic size — then `git init` + CI.

## 4. Verdict — **Conditional**

Production-ready **for its documented single-operator, loopback-bound local use**,
subject to two conditions:
1. **Fix the two quadratic dedupe paths** before running semantic dedupe on a full
   ~30k dataset — this is the app's real input and it will appear to hang (H1/H2).
2. **If ever exposed beyond loopback**, the fail-open auth default (S1), absent
   rate limiting, and unlimited-budget default (D1) become real exposure and must
   be closed first.

Not a release blocker for local use, but **"not under version control" (O1) blocks
any team/CI workflow** and should be fixed immediately regardless.

## 5. Top issues (ranked by business impact)

### T1 · 🟠 High · Performance — O(N²) semantic dedupe rebuilds the whole index every row
- **File:** `app/refine/filters.py` L63–71 (`_dedupe_semantic`); same bug `app/filtering.py` L59–64 (`SemanticGate.check`)
- **Problem:** `np.vstack(kept_vectors) @ vector` (and `np.vstack(self._accepted) @ vector`) re-stacks the entire growing vector list on **every** iteration/candidate.
- **Why:** `np.vstack` copies all kept rows each call → O(N²) time and cumulative allocation.
- **Impact:** On the 30k-row `data_30k.csv` target, refine dedupe stacks a growing (n×256) array 30k times — hundreds of GB of churn, minutes of GC thrash, looks hung. The generation gate is bounded by the run target but slows every batch as a run grows.
- **Fix:** Keep one growing 2-D `np.ndarray` (append rows; matmul against the slice), stack once not per row. `filtering.py` already pre-stacks `self._reference` correctly — apply the same to `_accepted`.

### T2 · 🟠 High · Deployment — Not under version control (no history, rollback, or CI)
- **File:** repo root (no `.git`; `.gitignore` present but unused; no `.github/`/`.gitlab-ci.yml`)
- **Problem/Impact:** The detailed CHANGELOG bug-fix history exists only as prose — no commit history, no `git blame`, no bisect/rollback, and the ruff+mypy+pytest suite runs only when someone remembers. The workspace CLAUDE.md itself flags this.
- **Fix:** `git init`, commit, add CI running the three already-documented commands on push.

### T3 · 🟡 Medium · Performance/API — Blocking CPU/model work on the single event loop
- **File:** `app/routes/refine.py` L127–217, 286–300; `app/embeddings.py` L26–38
- **Problem:** `async def` handlers call synchronous heavy pandas/model2vec directly (no `asyncio.to_thread`). `dedupe_semantic` lazily triggers `StaticModel.from_pretrained` (model **download**) on the loop thread on first use.
- **Impact:** A blocking refine/import call freezes `/health`, all requests, and an in-flight generation run's async workers + heartbeat until it returns.
- **Fix:** Wrap heavy bodies in `await asyncio.to_thread(...)` (or make handlers `def` → Starlette threadpool). Pre-warm the embedding model at startup (lifespan already offloads the default-reference import this way).

### T4 · 🟡 Medium · Security — Fail-open authentication default
- **File:** `app/settings.py` L39, 63–66 (`auth_key=None`; `auth_enabled=bool(auth_key)`); `app/security.py` L25
- **Problem:** Unset `DATAPREP_AUTH_KEY` → auth disabled → `require_key` is a no-op → every data route open. `__main__` binds loopback (safe), but the documented `uvicorn --host 0.0.0.0` bypasses that with auth still off.
- **Impact:** A container/proxy deployment that forgets the key exposes the whole API (LLM spend, api_v3 push, upload/delete) with only a log line.
- **Fix:** Fail closed — require an explicit `DATAPREP_ALLOW_NO_AUTH=1` for keyless use; refuse to start (or force loopback) when auth is off and bind host is non-loopback.

### T5 · 🟡 Medium · Deployment/Cost — Shipped LLM budgets are effectively unlimited
- **File:** `config.yaml` L18–23 (`max_llm_calls: 100000000`, `max_tokens_total: 100000000000`)
- **Problem:** The default disables the per-run cost guard that CLAUDE.md lists as a guarantee ("cost control: every LLM stage respects run budgets"). Deliberate for local runs, but it is the **repo default**.
- **Impact:** A mis-scoped run bills to completion with no ceiling (the "71k for a 35k target" incident class, but paid). Per-run budget also only bounds a single request — nothing bounds cross-request spend (see T8).
- **Fix:** Ship a finite default; require opt-in for "unlimited"; document the trade-off in `.env.example`.

### T6 · 🟡 Medium · Architecture — `RunManager` god-class (persistence + lifecycle + worker)
- **File:** `app/runs.py` L70–358 (store 83–133, lifecycle 137–188, worker 192–358)
- **Problem/Impact:** Three responsibilities in a 368-line class; the parity-/atomicity-critical store must be reasoned about alongside LLM orchestration; store logic can't be tested in isolation. `refine/store.py` already shows the separation pattern.
- **Fix:** Extract a `RunStore` (state.json read/write/list/reconcile); keep `RunManager` as lifecycle + worker.

### T7 · 🟡 Medium · Maintainability — Parity-critical "combine text + clean" duplicated 3×; two divergent `split_labels`
- **File:** `refine/analyze.py` L25–30, `refine/prep.py` L22–26, `refine/combine.py` L73–76; `reference.py` L42–44 vs `textnorm.py` L39–43
- **Problem/Impact:** The text-combine+`clean_text` op (which must stay byte-identical to api_v3 for the ±0 row-parity guarantee) exists three times; `split_labels` exists twice with different NaN/separator behavior. A fix to one copy silently breaks parity/dedupe consistency in the others.
- **Fix:** Promote one `textnorm.combined_texts` and one `textnorm.split_labels`; have all callers import them.

### T8 · 🟡 Medium · API — No cross-request spend ceiling on cost endpoints
- **File:** `app/routes/seeds.py` L120–156, `app/routes/refine.py` L241–262, `app/llm.py` L55–61
- **Problem:** Each cost call builds a fresh `LlmSession` with fresh `Usage(0,0)`; the `Budgets` caps bound one request only. No per-key quota, daily cap, or circuit breaker.
- **Impact:** A leaked key or a buggy UI retry loop drives unbounded cost, each call individually "within budget." Compounds with T4/T5.
- **Fix:** A process-local global/daily accumulator (trivial on single-worker) independent of per-request sessions; document the auth-on + loopback preconditions near the auth toggle.

### T9 · 🟡 Medium · Correctness — `combine_datasets` raises uncaught `KeyError` → 500
- **File:** `app/refine/combine.py` L71–77 (via `routes/refine.py` L287–300)
- **Problem:** Assumes `text_columns ⊆ target_columns` with no validation; the route has no try/except → inconsistent columns yield an opaque 500 instead of the app's standard 400.
- **Fix:** Validate `text_columns ⊆ target_columns` at the top and raise a client-safe `ValueError` (the route maps `ValueError`→400 elsewhere).

### T10 · 🟡 Medium · Testing — Route error-status mappings (413 / 429 / 502) unpinned
- **File:** `tests/` (no `413`/`429`/`502` route assertions); gaps at seeds.py 129–132/150–153, refine.py 255–258, exports.py 71–72, security.py 62–64
- **Problem/Impact:** Happy paths + many 400/404/422/409 are covered, but the client-contract error codes 413 (upload cap), 429 (budget), 502 (upstream/PushError) are asserted nowhere; a refactor of the `except` chains passes CI silently.
- **Fix:** Thin route tests: upload>cap→413; budget-exhausted mock→429; mocked 5xx/`PushError`→502.

## 6. All findings by dimension

**Security** (also T4): 🟢 no CSP header (`main.py` 94–105; flagged 3×); 🟢 refine datasets stored un-PII-scrubbed (`refine.py` 127, `store.py` 52 — documented deviation); 🟢 CSV formula-injection not neutralized on export (`exporter.py` 51–69); 🟢 `safe_name` guards paths but not HTML-encoding (latent stored-XSS if any future consumer renders a name as HTML); 🟢 internal fs helpers `_load_vocab`/`load_reference` omit `safe_name` (defense-in-depth — callers already validate, not exploitable); 🟢 no rate limiting (documented v2); informational: gzip-bomb via allowlisted host (negligible). **Clean & verified:** `fetch.py`, `apiv3.py`, `llm.py` (key via `os.environ.get`, no default; errors class-name-only), `pii.py`, `config/settings` (no hardcoded secret), `main.py` 500-handler.

**Performance** (T1, T3): the two quadratics + event-loop blocking are the whole story; the rest of the hot paths are fine.

**Correctness** (also T9): 🟡 `list_datasets` row count uses physical-line count (wrong for multi-line CSV) + leaks an unclosed file handle (`store.py` 62); 🟢 `text_columns` unpacking assumes ≥2 cols, a 1-col reference imports then crashes later (`seeds.py` 88, `runs.py` 239); 🟢 `holdout_split` position→label→`isin` is fragile on a non-unique index (`prep.py` 65); 🟢 refine filter empty/no-label handling diverges from what `analyze` reports (`filters.py` 45–51/125 vs `analyze.py` 63); 🟢 review edits vs worker appends are lost-update-free only by an undocumented "no await in the critical section" invariant (`review.py` 51–63, `runs.py` 320–339).

**Architecture** (also T6): 🟢 `vocab_formats.py` (342 lines) bundles a ~250-line Turtle lexer/parser with the manual-list parser — split `vocab_turtle.py`.

**Maintainability** (also T7): 🟡 `_generate` ~145 lines mixes setup + orchestration; nested `concept_worker` cyclomatic >10 (`runs.py` 213–358); 🟢 `_bareword` has a duplicated/dead `else`-return branch (`vocab_formats.py` 142–143).

**API** (also T8): 🟢 `LlmConfigError`→502 for a missing local key (should be 500/503; `seeds.py`/`refine.py`/`llm.py`); 🟢 security headers missing on unhandled-500 responses (BaseHTTPMiddleware post-processing skipped; `main.py` 92–105); 🟢 artifact list endpoints uncapped and re-scan on each call (`vocabs.py` 100–109 re-parses every vocab; `/runs` returns all when `limit` omitted). **Well done:** consistent `{"detail":...}` shape, 404-vs-400 by rule, every outbound call timed out.

**Testing** (also T10): 🟢 `test_run_honours_configured_concurrency` asserts the **exact** peak (`==2`/`==5`) off overlapping sleep windows — could under-count on a starved CI loop; use `>=`/tolerance (`test_runs.py` 336–378); 🟢 auth-required pinned once per router, not per mutating endpoint — add a parametrized "protected routes→401" table test. **Well done:** separation guarantee pinned via AST import-graph **and** behavioral status filtering **and** e2e; all network mocked at the httpx-transport boundary; SSRF fully unit-tested.

**Frontend/UX**: 🟡 hardcoded English strings bypass i18n despite the "full DE/EN" claim — skip-link (`index.html` 11), `nav`/field `aria-label`s (34, 126, 129), `#run-uris` placeholder (128), `title` (45), `<title>` (6), "loading…" (94); the completeness tests can't catch text that never enters i18n (WCAG 3.1.2 concern for DE screen-reader users); 🟢 audit action renders a fetch body without checking `res.ok` (a 5xx body shows as the report), tab bar isn't a formal ARIA `tablist`, list refreshes show no loading state (`runs.js` 108–113). **Verified clean:** no XSS (`textContent` everywhere; `innerHTML` only on in-code i18n constants), no CDN/hotlinked assets, AA contrast tokens, `:focus-visible` never removed, reduced-motion honored, `aria-live` regions present, data preserved on error.

**Dependencies**: 🟡 all 11 direct deps use `>=` floors and the documented setup installs those (lock bypassed → non-reproducible resolution); 🟡 `requirements.txt` claims a "hash-pinned" lock but the 59-line lock has **0** `--hash` lines (verified) — version-pinned only; 🟢 no CVE scan possible (`pip-audit` absent); 🟢 lock header comment misplaced mid-file. Pins look current (fastapi 0.139, pydantic 2.13.4, numpy 2.5.1, pandas 3.0.3, openai 2.45.0); all direct deps used.

**Documentation**: 🟢 README "162 tests" is stale (~219 collected); 🟢 "numpy 2.4 stubs" rationale vs pinned `numpy==2.5.1` (README 18, CLAUDE.md 14); 🟢 `.env.example` omits `DATAPREP_DATA_DIR`/`RUNS_DIR`/`CONFIG_FILE`. Otherwise accurate (run command, security model, layout, DE ui-guide, CHANGELOG design notes all match code).

**Deployment/Ops** (also T2, T5): 🟢 plain-text (not JSON) logging — fine for local single-operator; secret hygiene verified good (auth-disabled log carries no value, `/config` returns env-var names not values, 500 handler sanitized).

## 9. Refactoring roadmap

**Phase 1 — unblock the headline flow + process (½–1 day)**
1. Fix the two quadratic `vstack` dedupe loops (T1) — one growing ndarray, stack once. *Perf, Correctness.* Add a test that dedupes a few-thousand-row frame in bounded time.
2. `git init` + commit + CI (ruff/mypy/pytest on push) (T2). *Deployment, Testing.*
3. Offload heavy refine/import bodies to `asyncio.to_thread` + pre-warm the embedding model at startup (T3). *Perf, API.*

**Phase 2 — exposure & cost safety (1–2 days)**
4. Fail-closed auth opt-in + non-loopback guard (T4); finite default budget + opt-in unlimited (T5); process-local cross-request spend cap (T8). *Security, Deployment.*
5. Add CSP; neutralize CSV formula-injection on human-downloadable exports; `safe_name` in the two internal helpers. *Security.*

**Phase 3 — structure & parity (2–4 days)**
6. Extract `RunStore` from `RunManager` and split `_generate`'s setup from orchestration (T6). *Architecture, Maintainability.*
7. Promote single `textnorm.combined_texts` + `textnorm.split_labels`; delete the duplicates (T7). *Maintainability — protects api_v3 parity.* Split `vocab_turtle.py` out.
8. `combine` column validation → 400 (T9); the 413/429/502 route tests (T10); parametrized per-endpoint auth test.

**Phase 4 — polish (ongoing)**
9. i18n the remaining UI strings + a lint/test that flags hardcoded `aria-label`/`placeholder`/`title`; ARIA tab pattern; loading states.
10. Make the lock the canonical install path + `--hash` entries + `pip-audit` in CI; doc sync (test count, numpy, env-vars); JSON logging if ever a shared service.
