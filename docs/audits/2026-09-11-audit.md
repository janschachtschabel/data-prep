## 1. Executive summary

data-prep is in materially better shape than in July. The three headline
findings then — the quadratic semantic dedupe, no version control and no CI,
the fail-open auth default — are fixed, and the new table layer (import in four
formats, rules, columns, duplicates, join, profile, viewer) came with a test
suite that has grown from ~219 to 538 tests running in 24 s. The security
posture is sound for its intended deployment (one operator, one key, behind a
reverse proxy): constant-time key compare, loopback-only keyless mode, strict
CSP, sanitized 500s, SSRF guards on both outbound paths, a decompression-bomb
ceiling on gzip imports, and an atomic refine store.

The top three risks now are (1) the **largest input path still runs on the
event loop** — a gzipped upload inflating to 200 MB is parsed inline, during
which `/health` and run polling stall and the container health check can
trip; (2) **four stores still write in place** (seed sets, references,
vocabularies, run state), the same defect class fixed for refine datasets in
`13b80d1` — one corrupt seed-set file takes the whole Seeds tab down; and (3)
two latent auth-path weaknesses: a **placeholder key from `.env.example` is
accepted as a real key**, and a non-ASCII key header makes the auth dependency
**raise a 500** (logged with a full traceback, twice) instead of answering 401 —
triggerable without credentials.

The single most important action: offload the three synchronous import/fetch
bodies to a thread and route every store write through the one atomic helper —
half a day, and it removes the two findings that can actually lose data or
availability.

## 2. Overview

**Stack.** Python 3.12, FastAPI + uvicorn (single worker), pydantic v2 +

## 4. Verdict — **Conditional**

Production-ready for the intended deployment (single operator, strong key,
behind a TLS reverse proxy, loopback-bound compose) **once these five are
done** — none is more than a few hours, and none needs a design change:

1. P1 — offload `read_table` / `ingest_reference` / `fetch_json` to a thread.
2. L1 — route the seed, reference, vocabulary and run-state writes through one
   atomic helper.
3. S2 — refuse the `change-me` placeholder key at startup.
4. S1 — compare the API key as bytes so a non-ASCII header answers 401.
5. D1 — add `pip-audit` to the CI gate.

Not ready for an open-network deployment without a rate limiter in front of
`/auth/check` (S3) — a reverse-proxy limit is the intended answer; slowapi is
a documented v2 candidate.

## 5. Top issues (ranked by business impact)

### T1 · 🟡 Medium · Performance — the largest input path runs on the event loop
```
File:     app/routes/tables.py            Lines: 66–84  (import_dataset)
          app/routes/references.py        Lines: 55–70  (import_reference)
          app/routes/vocabs.py            Lines: 154–160 (fetch_vocab → fetch.py 40–49, sync httpx.Client)
Problem:  read_table (gunzip up to max_upload_mb×10 = 200 MB, CSV/JSON parse,
          flatten), ingest_reference (parse + per-cell regex scrub) and the
          synchronous HTTPS fetch (timeout 20 s) are awaited nowhere — they
          run inline in async handlers. The smaller table ops in the same
          file are offloaded with asyncio.to_thread; the biggest one is not.
Why:      One worker, one loop. While a 20 MB gzip import parses, /health,
          run polling, and every other request wait.
Impact:   Docker HEALTHCHECK (timeout 5 s, 3 retries) can mark the container
          unhealthy during a large import; the UI freezes; a background run's
          state flushes queue up.
Fix:      await asyncio.to_thread(read_table, payload, ...) and likewise for
          ingest_reference and fetch_json (or make fetch_json async on
          httpx.AsyncClient — the openai SDK already pulls it in).
```

### T2 · 🟡 Medium · Correctness — four stores still write in place
```
File:     app/seeds.py                    Lines: 155–157 (save_seed_set: write_text)
          app/routes/references.py        Lines: 69–70   (to_csv + write_text)
          app/reference.py                Lines: 136–137 (seed_default_references)
          app/routes/vocabs.py            Lines: 77–80   (_store: two write_text)
          app/run_store.py                Lines: 29–33, 71–73 (tmp + replace, no cleanup on failure)
          app/review.py                   Lines: 59–63   (same)
Problem:  13b80d1 made refine datasets all-or-nothing through
          refine/store._replace_atomically; the other stores were left as
          they were. A crash, kill or full disk mid-write leaves a truncated
          JSON/CSV in place.
Why:      list_seed_sets (seeds.py 167–171) json.loads EVERY file: one
          truncated seed set turns the whole Seeds listing into a 500 until
          someone deletes the file by hand. A half-written reference CSV
          loads as a shorter table with no error at all.
Impact:   Data loss that looks like corruption; the Seeds tab unusable.
Fix:      Move _replace_atomically to a shared module (app/atomic.py) and use
          it in all six places. run_store/review gain the .tmp cleanup.
```

### T3 · 🟡 Medium · Security — the example placeholder key is accepted as a real key
```
File:     .env.example                    Lines: 10, 24  (DATAPREP_AUTH_KEY=change-me, DATAPREP_APIV3_KEY=change-me)
          app/settings.py                 Line:  39      (auth_key: str | None = None — any string is a key)
          docker-compose.yml              Line:  32      (:? checks the variable is SET, not that it was changed)
Problem:  The documented setup is `cp .env.example .env` then edit. Skip the
          edit and the instance starts with the key "change-me", auth
          reported as enabled, no warning.
Why:      A known literal is not a secret. The startup warning covers the
          keyless case but not this one.
Impact:   Anyone who has read the repository can log in.
Fix:      A settings validator that refuses the literal placeholder at
          startup (fail closed, same posture as the non-loopback 403):
            @field_validator("auth_key")
            def _no_placeholder(cls, v): if v == "change-me": raise ValueError(...)
```

### T4 · 🟡 Medium · Security/API — a non-ASCII key header is a 500, not a 401
```
File:     app/security.py                 Line:  58      (secrets.compare_digest(key, settings.auth_key))
Problem:  compare_digest on str requires ASCII. Starlette decodes header
          bytes as latin-1, so any byte ≥ 0x80 in X-API-Key reaches the
          compare as a non-ASCII str → TypeError. Verified: raw ASGI request
          with b"sch\xfcssel" → status 500, body "Internal server error.",
          traceback logged by both the error middleware and the app handler.
Why:      The auth dependency must never raise for input shape; a 500 here
          is both a wrong contract and an unauthenticated log-flooding lever
          (two full tracebacks per request).
Impact:   Log noise at will; monitoring on 5xx rates fires; a client with a
          key containing "ü" is told the server is broken.
Fix:      secrets.compare_digest(key.encode(), settings.auth_key.encode())
```

### T5 · 🟡 Medium · Dependencies/Deployment — no vulnerability scan in the pipeline
```
File:     .github/workflows/ci.yml        Lines: 43–50   (ruff, mypy, pytest — no audit step)
          requirements-dev.txt            (pip-audit absent)
Problem:  The lock pins 56 packages; nothing checks them against the
          advisory database. Today's manual run: 0 known vulnerabilities —
          but the next openai/fastapi advisory would land unnoticed.
Impact:   Silent exposure window between an advisory and the next manual run.
Fix:      pip-audit>=2.7 in requirements-dev.txt (dev-only tool, justification:
          supply-chain gate the CLAUDE.md convention calls for) + a CI step
          `python -m pip_audit -r requirements.lock --no-deps`.
```

### T6 · 🟡 Medium · Testing — auth is enforced per router, but no test proves it for every route
```
File:     tests/test_system.py            Lines: 15–39   (auth on /auth/check only)
          tests/test_*.py                 (one 401 check each in 10 files, for ~10 of 40 routes)
Problem:  Every data router carries dependencies=[Depends(require_key)], which
          is the right structure — but a new router added without it would
          pass the whole suite.
Impact:   The most important invariant in the app rests on convention.
Fix:      One parametrized test walking app.routes: every path except
          /health, /ui*, /docs*, /redoc*, /openapi.json answers 401 without

```

### T7 · 🟡 Medium · Performance — `GET /refine/datasets` re-reads every table
```
File:     app/refine/store.py             Lines: 73–83   (list_datasets)
          app/routes/refine.py            Lines: 121–123 (not offloaded)
Problem:  For each stored CSV, the header is parsed and then column 0 of the
          ENTIRE file is read to count rows — on every list call, inline on
          the loop. The UI lists after every import and every apply from two
          tabs (refine.js 36, tables.js 80).
Impact:   O(total rows across all datasets) per click; with a few 400k-row
          working tables that is seconds of loop time per action.
Fix:      Record rows+columns once at save time (save_dataset already knows
          them) in the sidecar and read that; fall back to counting for
          files without one. Offload the fallback.
```

## 6. All findings by dimension

### Security
- **S1** 🟡 non-ASCII key header → 500 (`security.py:58`) — T4.
- **S2** 🟡 placeholder key accepted (`settings.py:39`, `.env.example:10`) — T3.
- **S3** 🟢 no rate limit on `/auth/check` (`routes/system.py:23–29`); online brute force is bounded only by key entropy. Documented v2 (slowapi); reverse-proxy limit meanwhile. README should say so.
- **S4** 🟢 `apiv3.py:17,42,76` allows a plain-`http://localhost` push target carrying the api_v3 key — documented dev convenience; keep, but the README security model should name it.
- Verified sound (no finding): constant-time compare; keyless mode loopback-only with 403 elsewhere (`security.py:50–57`); `safe_name` rejects `..`, `/`, `\`, leading `.`, NUL; upload cap streamed (`security.py:98–112`); gzip bomb ceiling (`tabular.py`, `tables.py:79`); HTTPS-only + allowlist + no-redirect + streamed cap on fetch (`fetch.py:29–49`); push host allowlist (`apiv3.py:41–43`); CSP `default-src 'self'` + frame-ancestors none + nosniff + no-referrer (`main.py:101–111`); sanitized 500 handler (`main.py:75–79`); `/config` returns env-var names only (`system.py:45–50`); keys never in `state.json` (`runs.py:86–89,172–174`); UI keeps keys in sessionStorage only, no `innerHTML` on data (only on i18n constants, `i18n.js:1091`); no CDN assets (`index.html:8`); ruff `S311` hits (`prep.py:46`, `runs.py:259`, `seeds.py:107`) are sampling, not crypto — false positives; `vocab_turtle.py:134` `assert` guards an invariant the dispatcher guarantees — harmless under `-O`.

### Logic & Correctness
- **L1** 🟡 in-place writes in seeds/references/vocabs; no `.tmp` cleanup in run_store/review — T2.
- **L2** 🟢 `main.py:48` `asyncio.create_task(...)` result discarded — the loop holds only a weak reference, so the default-reference import task can be garbage-collected mid-flight (documented asyncio caveat). Fix: keep it on `app.state.startup_task`.
- **L3** 🟢 `safe_name` (`security.py:81–95`) has no length bound and path-parameter names (`/{name}` in five routers) are unbounded, unlike body/form names (`max_length=100`). On Linux a name over 255 bytes makes `Path.exists()` raise `ENAMETOOLONG` → 500 (verified in `python:3.12-slim`); on Windows it is a 404. Fix: `len(name) > 100` → 400 in `safe_name`.
- **L4** 🟢 Windows-only: `safe_name` accepts reserved device names (`con`, `nul`, `aux`); irrelevant in the Linux image, worth a comment.
- Verified sound: tolerant `read_samples`; resume rebuild counts only kept samples; `stop` event + post-acquire re-check in the worker (`runs.py:276–282`); `_reserve_call` counts before awaiting (`llm.py:172–183`); rule comparison typed by the JSON value; composite keys need every part; join ceiling per `how`.

### Performance
- **P1** 🟡 event-loop blocking on import/reference/fetch — T1.
- **P2** 🟡 `list_datasets` O(rows) per call — T7.
- **P3** 🟢 `routes/vocabs.py:104–105` parses every vocabulary in full to list name/title/count; `routes/refine.py:254` serializes the whole frame inline for push; `label_audit` combines texts inline (`refine.py:208`). Small files today; same fix pattern as P1 when they grow.
